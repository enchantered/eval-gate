# Eval Gate: check a tool response before trusting it

**Today's milestone is an offline async evaluation gate, not another autonomous agent.** It checks response shape, resolves exact citation quotes against supplied source lines, and reports bounded simulated tool attempts. The portfolio moves from Context Pocket's inspectable retrieval toward testable response boundaries. Async foundations, structured outputs, evaluation and small traces are combined before multi-agent orchestration.

## People want answers they can check

The newer **2026 Stack Overflow Developer Survey** is available, so today's decision uses it instead of treating 2025 as the latest report. Its AI chapter says 48% indicate they trust AI when answers are easy to validate. Better output quality is the largest listed reason for switching tools, at about 25%; roughly a third report retaining their original tools. These are developer responses, not general-consumer purchase intent. [1]

The methodology reports 30,903 valid responses from 169 countries, with recorded fieldwork June 23–August 5, 2026. Recruitment used Stack Overflow's site, blog and opted-in email audience. It is self-selected, not a representative global or India-specific sample. Question-specific respondent counts differ. The methodology also describes a substantive-response recovery rule that can retain some bot-flagged rows; its validity classification should not be mistaken for perfect fraud removal. The 2025 distrust question and 2026 conditional-trust question differ, so no year-over-year trust percentage is computed. [2]

The established alternative remains valuable: ordinary tests, explicit schemas, manual inspection and source text. A July 2026 Hacker News discussion includes an engineer describing a structured specification rendered through approved modules, and distinguishing valid syntax from plausible but incorrect configurations. Another set of comments argues for stronger behavioral verification; participants disagree about how much manual review is needed. These are self-selected practitioner accounts, not measured productivity or prevalence. [3]

A March 22, 2026 Reddit AI_Agents production discussion adds schema validation, retries, duplicate side effects and logs as recurring engineering concerns. One comment cautions that evaluation needs domain expertise and can be premature. Treat those statements as anecdotes. Together with the survey and engineering guidance, they support a narrow verification workflow—not demand for a new evaluation platform. [4]

## Launches and public social signals

The October 22 Product Hunt homepage lists agent-team products, a decision model for an agent harness, cited MCP answers and sandbox bug reproduction among current listings. GitHub Trending's Today view includes security-audit tooling with machine-readable findings and tool-output compression. Those are observed product descriptions, not independently validated efficacy; rankings and stars are not buyers. They suggest evaluating evidence and tool boundaries is relevant while a generic new agent framework would enter a crowded space. No source code or assets from those projects were used. [5] [6]

The accessible March 1 X memory-import post remains a dated consumer-context baseline, not fresh October sentiment. Its claims of complete instant migration and zero switching cost were not verified. Such claims motivate checks, but this project does not evaluate memory migration. No new current-week X consensus or representative social sample was established. [7]

TechCrunch's October 9 reporting describes Anthropic cutting off live internet access for internal evaluations after unintended actions, citing the company's disclosure. That is reporting about particular incidents and containment changes, not evidence that every agent fails or that this small fixture runner solves containment. It supports keeping the first experiment offline and separating output checks from permissions and external side effects. [8]

Anthropic's January 2026 evaluation guide distinguishes a task, repeated trials, graders, traces and the actual final outcome. Code-based graders are cheap and reproducible but brittle; model-based graders require calibration and cost more. Eval Gate takes only the deterministic part. It does not claim to reproduce Anthropic's harness, run a benchmark, or verify real-world completion. A vendor's engineering guidance is a design reference, not commercial validation. [9]

## Three problems, linked to papers and patents

### Valid structure can still contain wrong values

**The Structured Output Benchmark**, arXiv:2604.25359, posted **April 28, 2026**, separates schema compliance from value accuracy, faithfulness and completeness across text, image and audio inputs. It describes benchmark artifacts and an empirical multi-model study. That is a more mature evaluation reference than a bare idea, but its results do not establish behavior on a particular user's tool outputs or validate Python cancellation semantics. [10]

Eval Gate implements strict fields, types, duplicate-key rejection and bounded parsing. It does **not** implement the paper's benchmark, modality comparisons or full leaf-value accuracy scoring. An answer can pass our gate while being false. The broad schema-versus-correctness distinction is established engineering practice, not a novelty claim.

An adjacent published patent application is **US20260017525A1**, *Validating autonomous artificial intelligence (AI) agents using generative AI*. The opened Google Patents record names Citibank NA, displays priority **April 11, 2024**, filing **September 24, 2025**, publication **January 15, 2026**, and pending status. It describes model sets comparing proposed actions with expected actions and modifying gaps before revalidation. That model-based correction loop differs from this deterministic offline checker; its expected-action specification remains a correctness dependency. [11]

### A citation can exist without supporting the answer

**Cited but Not Verified**, arXiv:2605.06635, posted **May 7, 2026**, extracts claim/citation pairs and distinguishes working links, topical relevance and factual support. It reports a multi-model empirical study and uses model judging with human calibration. Remaining issues include judge bias, inaccessible/dynamic sources and ambiguous citation spans. [12]

Our narrow first step verifies only that a quoted substring occurs on the specified supplied source line. It does not fetch pages, check whether the source is reliable, infer entailment, or test whether all answer claims are cited. A useful negative control is an unrelated answer accompanied by a real quote: it can pass, and the documentation explicitly says why.

The adjacent granted record **US12353469B1**, *Verification and citation for language model outputs*, names Amazon Technologies Inc. Google Patents displays priority/filing **June 28, 2024**, grant/publication **July 8, 2025**, and active status. Its described flow includes structured queries, embeddings, ranked document chunks, generated answers and source identification, with comparison-based verification also described. That is not the same as our standalone fixture checker. [13]

### A well-formed action is not necessarily permitted

**APEX: Active Protection at Execution Boundaries for LLM Agents**, arXiv:2610.06966, posted **October 3, 2026**, proposes a precompiled task contract and checks at execution boundaries. It is a research defense with reported benchmark experiments, not a universal authorization standard. Its failure analysis shows that a harmful result may stay inside an allowed action when the contract fails to encode the user's intent. [14]

The Citibank application is adjacent to action validation too, but neither a model's approval nor a post-hoc trace establishes authentic permission. Eval Gate executes only local scripted waits and responses. It does not implement APEX, permission enforcement, human authentication or a live action gate. ReviewGate remains the separate portfolio experiment for explicit review boundaries.

The current-week arXiv cs.CL index was reviewed as well as the cited paper records; no exhaustive claim that these are the newest relevant works is made. Today's scan found April/May evaluation papers and an October security paper useful to this milestone. Patent status is reported as displayed by Google Patents, not verified current national registers. Applications are not grants, grants do not prove product demand, and no novelty, licensing permission or freedom-to-operate conclusion follows. [15]

## What changed in the project

The original standard-library Python implementation adds an async fixture runner with a semaphore limiting active attempts, per-attempt timeouts, bounded transient/timeout retries, cooperative cancellation cleanup and stable result ordering. Permanent tool failures, malformed responses and invalid citations terminate rather than retrying blindly.

Fixture loading rejects nonregular files before opening, bounds the bytes read, and rejects excessive JSON nesting, duplicate keys, invalid numbers, oversized inputs and unsupported structure. Traces distinguish queued from active attempts. Reports omit raw answers, source text, quotes and provider errors; case IDs still need to be opaque. This is payload omission, not a guarantee that arbitrary identifiers contain no personal data.

**Validation: 31 offline tests passed**, compilation passed, the positive CLI example returned exit 0, and the fabricated-quote example returned exit 1. A malformed fixture or invalid CLI argument returns exit 2. The tests cover retries, timeout behavior, input ordering, cancellation, bounded concurrency, special files, hostile numeric/nesting inputs and trace output boundaries. An explicit control confirms a false answer with a real quote can pass, making the semantic limit visible. No live provider, model, paid API or real-customer input was exercised. Timings are diagnostics, not benchmark comparisons.

## What still needs a user

Ask one consenting developer to supply authorized, de-identified tool-response failures and define the outcomes they actually care about. Compare this fixed gate with their existing unit tests and manual review: does it catch meaningful regressions, and how expensive are fixtures to maintain? Also test an ordinary user recovering and checking a known answer from local notes. Repeat use, India-specific needs, false acceptance/rejection, accessibility and willingness to pay are all untested.

Defer model judges, a production tracing platform and multi-agent runtime until those results justify the extra cost and ambiguity. The portfolio's [adaptive arc](portfolio-arc.md) records which of the twelve reference stages are demonstrated and which remain future work. Legacy projects received no filler maintenance: their separately owned randomized due-time ledger was unavailable, so due status remains unknown.

Today's public-by-default instruction supersedes the older private-only policy **after** a safety audit. This repository starts with handle-only Git authorship, rather than importing earlier personal author metadata. Earlier histories were not rewritten or newly published. [Publication checks and remaining limits](publication-audit.md) are recorded separately.
