# Context Pocket: finding useful answers again

**Build a small offline search utility, not another AI memory service.** Context Pocket searches user-provided text and Markdown, returns source paths and line numbers, and opens neighboring source lines. It uses no model, embeddings, account, upload or persistent index. This is a portfolio experiment with unvalidated demand, not a novel retrieval algorithm or an investible-business claim.

## Why this everyday problem

AI conversations accumulate useful instructions, but finding the original answer is a different task from asking a model to reconstruct it. A June 9–10, 2026 OpenAI developer-community exchange describes exact-term searches returning unrelated conversations on web and Android. The thread closed June 14; it does not establish that the bug remains unresolved or affects most users. The adjacent LLM Chat Explorer project already offers local ChatGPT/Claude archive browsing and search. These independently expose a retrieval workflow, not a measured high-frequency market. [1] [2]

Memory portability is also a product concern. The Times of India reported Claude's memory-import feature on March 3, 2026. Simon Willison's March 1 developer note shows that the import workflow uses a prompt to produce transferable text. A March 1 X post promotes the same workflow with claims of complete, instant migration. That post is an attention signal, not proof that exports preserve everything, that switching costs disappear, or that it caused App Store rankings. Context Pocket does not import provider memories or claim complete chat exports. [3] [4] [5]

The enduring alternative is a folder of notes, copied text and ordinary file search. We are testing whether a bounded, inspectable search/readback workflow helps users recover a known answer. We are not assuming AI must replace those tools. Unlike existing chat-export viewers, this first version deliberately accepts only plain text and Markdown, not native provider JSON; that simplicity also imposes extra preparation effort.

## What the broader signals support

Product Hunt's LumiChats Offline page describes a local/offline AI product, including an August 2, 2026 launch. Its adjacent document-chat features make this a crowded category, not an untouched market. The October 21 GitHub Trending snapshot surfaced verification/security and deterministic information tools. Those changing rankings, stars and launch badges indicate developer attention, not buyers or retention. A Reddit LocalLLM builder post, displayed as seven months old, adds one offline/travel motivation; its exact publication date was not verified and it is not independent consumer adoption evidence. [6] [7] [8]

For enterprise foundations, McKinsey's 2026 AI Trust Maturity Survey covered roughly 500 organizational respondents with AI governance, risk or investment responsibility, surveyed December 2025–January 2026. Nearly two-thirds identified security/risk as the top barrier to scaling agentic AI. This supports investigating authorization and controls, not demand for a specific consumer search utility. Our historical log preserves separate U.S. consumer-adoption findings; those surveys use different definitions and cannot be combined with this organizational sample. India-specific adoption and willingness to pay for this project remain untested. [9]

Three directions were compared. **Context recovery** has a bounded original implementation and observable source verification, so it is today's choice. **Agent-action authorization** is important but overlaps ReviewGate and needs identity/integration work before a real pilot. **Return/renewal deadlines** remains an existing Return Window experiment; there is no reason to build another near-duplicate. Frequency, retention and payment remain open questions for all three.

## Problems linked to papers and patents

### Recovering context without losing its source

The current arXiv cs.AI index was inspected on October 21. A newly listed preprint, **Evolving Semantic Indexes for Generative Retrieval**, arXiv:2610.28568, was submitted **October 20, 2026**. It uses a locally served 31B model to evolve retrieval programs and a small proxy decoder for feedback. The authors report that proxy improvements transfer for some semantic-index changes but not reliably for training objectives or the entire pipeline. This is benchmark research, not a consumer archive product, and is much more computationally demanding than our lexical search. [10] [11]

**TRACE**, arXiv:2607.00339, submitted **July 1, 2026**, is more directly about conversational evidence: temporal graphs represent sessions, events, updates and contradictions. Vector retrieval and graph paths aim to distinguish historical from current facts. Incremental graph construction and turn-level time anchoring remain research gaps. Context Pocket implements none of that method: source readback is transparent but cannot resolve contradictions, paraphrases or stale facts. [12]

The adjacent **US20260233597A1**, *Trust-aligned AI governance and memory vault system*, was published **August 13, 2026**, filed **April 3, 2026**, with claimed earlier priority beginning **September 28, 2021**. The opened Google Patents record lists an individual assignee and pending status. It describes multi-tier memory and trust-gated operations, not the same narrow file-search utility. Its continuation history and claims need professional review before drawing legal conclusions. [13]

### Knowing what an agent may do before it acts

**Proof-Carrying Contracts**, arXiv:2610.28484, submitted **October 20, 2026**, proposes an execution gate called an Airlock. An agent supplies a machine-checkable proof that an operation preserves agreed constraints under its model; the gate controls access. The abstract's guarantees depend on the modeled conditions and their connection to the real world. A new theoretical preprint does not establish broadly deployed safety, usable proof generation or correct real-world models. ReviewGate is not an implementation of this framework. [14]

An older complementary paper, **Authenticated Delegation and Authorized AI Agents**, arXiv:2501.09674, submitted **January 16, 2025**, proposes identity/delegation using OAuth and OpenID Connect. Scoped authority, successful execution and authentic human approval remain distinct problems. The same August 2026 memory-vault patent application mentions operation-specific tokens and approval gates; it is an **A1 application, not a granted patent**, and its disclosure proves neither implementation nor buyer need. [13] [15]

### Turning a deadline into a trustworthy calendar entry

**Event Extraction in Large Language Model: A Holistic Survey**, arXiv:2512.19537, submitted **December 22, 2025**, discusses hallucinated event triggers/arguments, structured-output failures and temporal linking. It is a survey, not a benchmark establishing reliable purchase-return extraction. No newer directly relevant deadline-extraction paper was verified in this bounded scan. The safe small-MVP boundary remains explicit user-entered dates and confirmation rather than automatic interpretation of retailer rules. [16]

Older prior art is substantial. **US8832205B2**, *System and method for extracting calendar events from free-form email*, names Lextine Software LLC. Its filing/priority date is **November 2, 2009**, its application was published **May 5, 2011**, and its grant was published **September 9, 2014**. It combines keyword/NLP processing with calendar generation. **US20240273433A1**, *Reminder system*, names DOCSOF LLC; the present filing is **September 18, 2023**, publication **August 15, 2024**, and claimed earliest priority **February 4, 2006**. It describes document/email-linked reminders, due dates and calendar views. These are a grant and an application respectively; publication dates are not priority dates. Neither proves demand or technical novelty for Return Window. [17] [18]

These are relevant records found, not an exhaustive newest-paper or patent-family search. Patent metadata came from Google Patents, not verified current national registers. Papers are not product validation; patents are not proof of implementation, validity, licensing permission or freedom to operate. No proprietary code, paper implementations, assets or private user content were copied. No legal clearance is claimed.

## What shipped and how to validate it

The original Python 3.11+ utility performs case-insensitive literal AND matching on individual lines, with deterministic path/line ordering and explicit truncation flags. It supports readback with context, rejects invalid text and special files, avoids symlink traversal, bounds input size, and escapes terminal controls in paths and text. It does not generate answers or verify the truth of retrieved text. Paths and line numbers can change when files are edited.

**22 offline tests pass**, along with compilation, JSON-search and source-readback smoke checks. Tests cover matching, ordering, malformed UTF-8/NUL input, limits, hidden files, path traversal, symlinks, named pipes, unreadable-directory handling, truncation and terminal control escaping. Actual ordinary-user usability, native export preparation, Windows portability and accessibility still need testing. No live model call was made.

Before adding semantic search, test five consenting users retrieving known answers from their own authorized exports. Compare success and time with their usual app search and ordinary file search. Observe whether preparation costs exceed retrieval benefits. Ask about weekly recurrence and willingness to pay separately; do not infer payment from stars, survey adoption or positive comments. Stop or change direction if users cannot prepare inputs or the tool is no better than their existing search.

Read-only heuristic scans covered tracked content and reachable history of the three existing local repositories: 15 commits/66 historical blobs in the venture workspace, 15/66 in Occlusion Lab after fetching ReviewGate's branch, and 1/9 in Return Window.
